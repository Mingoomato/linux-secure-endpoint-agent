# Architecture

The endpoint has a durable SQLite spool and a TLS 1.2-or-newer client. Synthetic event creation hashes the payload, assigns a durable sequence, writes the row before networking, sends bounded batches to a loopback mTLS endpoint, and removes only IDs explicitly accepted or identified as duplicates by the authenticated server. Queue size and byte quotas stop unbounded growth; retry uses bounded exponential delay with jitter.

The reference server verifies each client-certificate chain and separates agent and operator common-name allowlists. Event ingestion requires an agent identity and commits event IDs under a unique agent/event key before acknowledgements. Policy publication requires an operator identity plus a bearer token; the server validates the restricted tenant policy, signs its exact bytes with Ed25519, and stores a monotonic revision. Agent fetch supports an ETag/304 unchanged response. The database contains event metadata/hashes and the current signed policy.

The agent and server each have a bounded JSON parser that enforces JSON number/whitespace grammar, duplicate-key rejection, maximum nesting, and a 1 MiB text cap. Separate parser tests guard both copies. The custom HTTP/1.1 subset limits headers to 16 KiB and bodies to 1 MiB, requires unambiguous Content-Length framing and JSON Content-Type for event batches, and requires HTTP 200 for event acknowledgements. Policy fetch accepts HTTP 200/304. It rejects Transfer-Encoding and duplicate framing/authentication headers, applies a 5 second per-I/O timeout, and enforces a configurable 10 second absolute HTTP header/body receive deadline after TLS peer and CN authorization. TLS handshake and route handling remain outside this deadline; the handshake itself has per-I/O limits but no total deadline. This is a deliberately limited lab implementation, not a general HTTP stack.

Policies are separately signed with Ed25519 over exact document bytes. Agent validation rejects unknown top-level/settings fields and unsafe actions, checks issued/expiry timestamps, tenant/root scope, and monotonic revision, then commits last-good state and audit in one SQLite transaction. TLS authentication does not replace detached policy signature verification. At runtime, the agent rechecks stored policy state: `telemetry_enabled` gates synthetic event creation and queue flushing, while `sample_rate` gates only new synthetic events. Missing policy fails closed, and an inactive gate keeps queued rows. `monitored_roots` are validated and counted but no file watcher consumes them; full runtime policy application remains partial.

A C transport probe is limited to loopback TCP connectivity; TLS is implemented only in the C++ agent/server.
