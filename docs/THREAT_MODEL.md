# Threat model

## Trust boundaries

- The endpoint accepts only loopback endpoints by default and validates the server trust chain plus DNS/IP SAN.
- The server requires mTLS and checks the client CA chain. Agent identities map from certificate CN/UUID to an enabled SQLite registry row and SHA-256 certificate pin; operator identities use a separate CN allowlist. Event payload agent_id must match the certificate identity. Operator enrollment/rotation/revocation routes and policy publication additionally require a bearer token read from a mode-0600 file and compared in constant time.
- Policies are untrusted even after TLS and require an Ed25519 signature, expiry, monotonic revision, tenant scope, allowlisted actions, and root scope validation.
- SQLite spool and server DB are local; files are created with restrictive permissions.
- Both JSON parser copies cap input at 1 MiB, limit nesting, reject duplicate object keys, enforce JSON number grammar, and allow only JSON whitespace.

## Data minimization

Synthetic health events and explicit `event.v1` imports are policy-gated. Long-running `run` mode now also watches active monitored roots with inotify and emits allowlisted filesystem metadata only. It never opens file content; the raw path is replaced with a per-store HMAC identifier before queue storage. Missing/expired policy or disabled telemetry prevents creation and pauses sending while existing queued rows remain stored; `sample_rate` gates new events. Symlink directories and cross-device subtrees are skipped; watch limits and overflow produce degraded coverage. The current collector builds and passes focused rename/watch-rebuild and queue privacy tests; genuine kernel overflow and namespace/resource fault paths remain unverified. Server logs contain generic request rejection summaries.

## Residual risks

The server is sequential. Its custom HTTP subset bounds headers to 16 KiB and bodies to 1 MiB, checks JSON media type and unambiguous framing, applies a 5 second per-I/O timeout, and enforces a configurable absolute TLS handshake deadline plus a separate HTTP header/body receive deadline after TLS peer and CN authorization. Both deadlines are 10 seconds by default and configurable from 100 to 60,000 ms; route handling remains outside the HTTP deadline. Rate limiting and broader availability controls are absent. Agent/server JSON parser implementations are duplicated and must stay in sync. Admin policy publication, conditional fetch, and a registry API for certificate enroll/rotate/revoke/re-enroll are implemented for the local lab; the newly added registry code is unverified. Runtime gates apply `telemetry_enabled` and `sample_rate` to synthetic, imported, and collector events. The inotify collector is metadata-only and has no initial content baseline; overflow recovery rebuilds watches but cannot reconstruct missed history. This new code is unverified. Revocation, certificate enrollment, production RBAC, prepare-before-commit watcher availability, and full runtime policy application remain incomplete. The optional local bootstrap file and the SQLite certificate registry are an identity mapping for this lab rather than a production enrollment system. Initial pinning is TOFU for pre-registered UUIDs; the registry endpoints have not been exercised after implementation. The server recomputes payload hashes from canonical compact JSON and rejects mismatches. The Agent requires HTTP 200 for event ACKs and accepts HTTP 200/304 for policy fetch. No HA, production PKI, public network service, or remote execution is provided.
